# 接入、打包与验收

## 1. 迁入现有 TS + Electron 项目

| 步骤 | 应做的改动 | 判断完成的依据 |
|---|---|---|
| 契约层 | 迁入 contracts、errors、validation；统一错误 envelope | 类型检查及边界测试通过 |
| 自动化层 | 迁入 Driver、Session、Mock；明确唯一 Manager | 重复动作仅执行一次；旧 snapshot 被拒绝 |
| Main 层 | 将五个 handler 接入已有主窗口注册表；使用该产品自己的固定 origin | 其他窗口、子 frame、错误 URL 均被拒绝 |
| Preload 层 | 合并五个具名方法，打包为单个 CJS | Renderer 无 Node，全量 ipcRenderer 未暴露 |
| UI 层 | 使用现有框架实现目标选择、观察、动作和取消 | Electron 集成测试可核对实际业务结果 |
| macOS 层 | 编译 helper，固定资源路径，保留正常授权入口 | 在真实 GUI 与打包版本逐项验证 |

参考工程没有引入 React/Vue、Vite 或 monorepo；迁入时复用已有技术栈即可。业务任务若需要计费、审计、租户权限或审批，放在 Main/受信服务的授权层中，不让模型 action 改写政策。

## 2. 构建与分发

运行 `npm ci` 后，先 `npm run typecheck && npm test`，再 `npm run native:build`。本机编译只产生本机架构的 helper；当前交付源码可重编译，资料包不包含 Electron runtime、node_modules 或本机 helper 二进制。

`scripts/build.mjs` 分别构建 Main、Preload、Renderer、CLI demo 与 Node 测试。Main/Preload 的 Electron import 保持 external，其余工程模块打入 bundle，发布时无需依赖原分析目录。Preload 为 CJS；不要仅把 TS 扩展名改为 js。

打包模板在 `packaging/electron-builder.example.yml`，用于合入项目已有发布流水线，尚未运行签名打包。示例 appId 必须替换；helper 作为额外资源放到 `Resources/bin/mac-ax-bridge`，与 Main 运行路径保持一致。Native 可执行文件须位于真实资源路径；ASAR 是虚拟归档，spawn 等系统调用不能按普通文件处理归档内可执行文件。[Electron ASAR 说明](https://www.electronjs.org/docs/latest/tutorial/asar-archives)

签名流水线需覆盖嵌入 helper、Electron 子组件与主应用，并按发布平台执行公证。本例没有提供虚构的证书、通用 entitlement 集合或自动发布命令。具体签名和公证配置应沿用项目实际工具与证书流程。[Electron macOS signing](https://www.electronjs.org/docs/latest/tutorial/code-signing)

OS 权限与“允许本次会话”分别验收：后者是本应用策略，不能替代 macOS 辅助功能权限。开发启动、签名包、改 bundle id、更换安装路径、升级后都应检查实际 TCC 归属和行为。权限缺失时让用户正常授权并重启必要组件，不通过修改 TCC 数据库解决。

## 3. 已有自动化检查

| 命令 | 检查层 | 不覆盖的内容 |
|---|---|---|
| npm run typecheck | strict TS | JS/Swift 运行结果 |
| npm test | 输入、发送者谓词、会话与子进程传输 | 真实 AX、OS 权限与签名包 |
| npm run demo | Mock 观察 → 动作 → 观察 → 取消 | Electron UI 与真实桌面 |
| npm run test:electron | 真实 Electron UI/Preload/Main/Mock、其他窗口拒绝 | 真实桌面 AX、签名包 |
| npm run native:build | Swift 可编译 | 实际 AX 正确性 |
| helper --self-test | 整数输入校验 | AX 与 GUI |

Electron 集成测试会打开本参考工程的窗口，仅操作 Mock Counter；测试结束自动退出。它把配置和临时文件放在 `build/`。受限命令沙箱可能无法启动 macOS GUI，应在正常桌面终端运行，不能为此关闭 Renderer sandbox。测试 harness 是受信本地测试代码，不是产品的任意代码执行接口。

## 4. 真实 macOS GUI 验收清单（待执行）

以下是进入真实桌面试用前应填写的验收，不代表本次已经通过。

| 情境 | 操作 | 预期 |
|---|---|---|
| 首次启动 | 计算器已运行，一个窗口，读取 AX | 返回有界完整树及 snapshot，无硬编码索引 |
| AX 动作 | 从新树选择一个可识别的数字按钮，press 后重读 | AX 值符合实际界面；异步更新可再次 observe |
| 完整刷新 | 保存旧 ref，重新 observe，再用旧 ref | STALE_SNAPSHOT，目标无动作 |
| 动作重复 | 同一快照并发提交两次 press | 最多一次执行，第二次被拒绝 |
| 权限缺失 | 未授予辅助功能权限，observe | PERMISSION_REQUIRED，不执行后续动作 |
| 应用未运行 | start 或 hello | TARGET_CHANGED/启动失败，租约释放 |
| 应用重启 | observe 后退出并重开计算器，再 act | TARGET_CHANGED，旧会话不可继续 |
| 多窗口 | 建立第二个 AX window，再 observe/act | UNSUPPORTED 或 TARGET_CHANGED，不猜测目标 |
| helper 崩溃 | 请求等待中终止 helper | DRIVER_LOST，pending 拒绝，旧通道不可重用 |
| 动作超时 | 构造慢响应 | 关闭 helper，不重试，报告结果未知 |
| 用户取消 | 长请求中点击取消 | 取消不等排队；退出后释放租约；旧响应不更新 UI |
| 用户主动操作 | 人为改变目标状态 | 当前首版无自动用户接管检测；手动取消并重新观察，验证此限制可接受 |
| 关闭/重载窗口 | 请求或授权对话框等待时关闭/重载 UI | 没有继续执行的无主会话，目标租约最终释放 |
| 签名包 | 在干净机器安装签名/公证版本 | helper 可找到且可执行，TCC 行为与产品指引一致 |
| 升级与架构 | 同版本重装、升级、arm64/x64 分别运行 | 资源、身份、权限和终止行为符合预期 |

涉及权限、真实应用重启、其他窗口和发布行为的项目应由操作者在独立测试会话逐项确认。自动化记录须区分“动作已发出”“驱动返回成功”和“业务结果已核验”。

## 5. 后续扩展的具体前置工作

截图：先完成操作窗口与截图窗口映射，再开放 screen recording 指引和图像 metadata；禁止靠“第一个窗口”隐式选择。

稳定等待：定义业务结果或 AX 状态变化条件，加入取消可中断的有界观察；超时后报告当前状态，不盲点重试。

差分：引入稳定内部 identity、full/diff/baseRevision，基线丢失或进程/窗口变化时退回 full。对重排、虚拟化列表和同名元素做误命中测试。

浏览器：独立 origin policy、tab claim、Frame/OOPIF/document 身份、locator 与 AX 能力；以明确的新契约接入，不能把 macOS index 随意复用于 DOM。

模型：加入受限 JSON 工具回路、上下文预算和结果断言后再做业务评测；任意模型 JS 若确有必要，需要另行设计 OS 隔离、资源预算与有限能力桥。
