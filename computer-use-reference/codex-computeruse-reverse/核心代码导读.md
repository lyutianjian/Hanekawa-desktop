# 按功能阅读 Computer Use 核心代码

这份材料提供两层真实提取代码和一层解释：

1. `core/formatted/`：安装包原码只做 AST 格式化，保留混淆变量。
2. `core/readable/`：在同一 AST 上按作用域改名，保留实际逻辑、字面量和导出；名称由本次分析赋予，部分局部变量仍保留短名。
3. 本文标注“解释性重写”的代码：用现代 async/await 和具名变量说明机制，省略项会列出；它不是从二进制恢复的原始作者源码。

提取文件的相对 import 保持原样，依赖未一并打包；它们用于阅读。需要运行原版函数时使用 reproduction-tests.mjs。18 个纯格式化版本都通过了 AST 一致性检查，阅读版均通过解析检查。

## 1. App 对象是绑定应用的闭包

真实实现：C03，第 8 行开始；C02 负责调用它。下面是解释性重写，省略输出发射、截图字节加载和其他动作：

```javascript
function bindApp(computer, appId) {
  return {
    async getAXState(options = {}) {
      const result = await computer.get_app_state({
        app: appId,
        disableDiff: options.disableDiffing,
      });
      return result.text;
    },
    click(target, options = {}) {
      const input = { app: appId };
      if (Array.isArray(target)) {
        [input.x, input.y] = target;
      } else {
        input.element_index = target;
      }
      if (options.durationMs !== undefined) {
        input.duration = options.durationMs / 1000;
      }
      return computer.click(input);
    },
  };
}
```

`calculator` 绑定仍存在，才能在后续调用继续使用。同一对象的存在不保证数字索引永远有效，索引还依赖最近的观察状态。真实实现会自动发射状态/图片，返回值再手动 write 会造成重复输出。

## 3. 授权前先固定输入

真实实现：C06 的 `freezePlainInput`，阅读版第 240 行。以下是解释性重写，保留关键步骤：

```javascript
function freezePlainInput(input, canonicalAppPath) {
  if (typeof input !== "object" || input === null) throw new Error("object required");
  const descriptors = Object.getOwnPropertyDescriptors(input);
  const app = descriptors.app;
  if (!app || !("value" in app)) throw new Error("plain app property required");
  if (typeof app.value !== "string" || !app.value.trim()) throw new Error("app required");

  const fixed = {};
  for (const [key, descriptor] of Object.entries(descriptors)) {
    if (!("value" in descriptor)) throw new Error("accessor rejected");
    Object.defineProperty(fixed, key, {
      configurable: false,
      enumerable: descriptor.enumerable,
      writable: false,
      value: key === "app" ? canonicalAppPath ?? app.value : descriptor.value,
    });
  }
  return Object.freeze(fixed);
}
```

危险结构的最小例子是 `get app(){...}` 在多次读取时返回不同目标。描述符检查不会先执行 getter。原版代码还会在策略完成后使用 canonical appPath 重新生成固定输入。该函数是浅层保护，不会递归冻结 input 中每个嵌套对象。

## 4. 应用策略与批准是连续两道处理

真实实现：C06 `withComputerUsePolicy`，第 10 行；授权请求元数据在约第 65 行之后。下面是控制流解释，省略 telemetry、persistent-state 判断、完整授权元数据和音频单独授权：

```javascript
async function runWithPolicy(toolName, input, execute) {
  const fixed = freezePlainInput(input);
  const policy = await client.getAppPolicy(fixed.app);

  if (policy.decision === "denied") throw new Error("organization policy");
  if (policy.decision === "forbidden") throw new Error("forbidden app");

  const approval = await nodeRepl.createElicitation({
    message: `Allow Computer Use to use "${policy.target.displayName}"?`,
    meta: {
      tool_name: toolName,
      tool_params: { app: policy.target.bundleIdentifier },
      persist: policy.allowPersistentApproval ? ["session", "always"] : ["session"],
    },
  });
  if (approval.action !== "accept") throw new Error("not approved");

  return execute(freezePlainInput(fixed, policy.target.appPath));
}
```

已保存的授权可由宿主返回，不代表每次动作都让用户重新点击确认。只读观察同样会经过相应应用访问入口，因为屏幕内容本身也受访问控制。

## 5. 点击的真实请求编码

真实实现：C07 `click`、`performAction`、`actionLocation`；C16 负责从 snake_case 参数转到此 client 的参数。下面保留请求形状，变量名作解释性改写：

```javascript
function actionLocation(input) {
  if (input.elementIndex !== undefined && input.elementIndex !== null) {
    return { elementID: { _0: String(input.elementIndex) } };
  }
  return { coordinate: { _0: [Number(input.x), Number(input.y)] } };
}

function encodeClick(input) {
  return {
    app: input.app,
    action: {
      click: {
        at: actionLocation(input),
        clickCount: input.clickCount ?? 1,
        mouseButton: 0,
      },
    },
  };
}
```

此解释片段固定 mouseButton 为左键并省略参数验证、按键和 duration；完整 client 支持左右中键并检查参数。`elementID._0`、`coordinate._0` 是原版实际结构，不是本文为了画图创造的字段。test-results.json 保存了原版 client 实际生成的请求。

## 6. 原生分帧的真实实现

下面直接摘自 C08 的阅读版，除前面定义的 `MAX_FRAME_BYTES = 8388608` 和错误类型依赖外未简化逻辑：

```javascript
function decodeMessageFrames(e) {
  const t = [];
  let n = 0;
  for (; e.length - n >= 4;) {
    const r = e.readUInt32LE(n);
    if (r > MAX_FRAME_BYTES)
      throw new SkyComputerUseTransportError(`Sky Computer Use native pipe frame is too large: ${r}`);
    const o = 4 + r;
    if (e.length - n < o) break;
    t.push(e.subarray(n + 4, n + o).toString("utf8")), n += o;
  }
  return { messages: t, remainingData: e.subarray(n) };
}

function encodeMessageFrame(e) {
  const t = Buffer.from(e, "utf8");
  if (t.length > MAX_FRAME_BYTES)
    throw new SkyComputerUseTransportError(`Sky Computer Use native pipe frame is too large: ${t.length}`);
  const n = Buffer.alloc(4 + t.length);
  return n.writeUInt32LE(t.length, 0), t.copy(n, 4), n;
}
```

阅读版第 185 / 200 行分别是两个函数。字符串长度不能直接作长度头，中文和 emoji 的 UTF-8 长度不同；实际测试包含分片切开 Unicode 字节的情形。解码函数只取出完整帧，JSON 解析和响应结构检查在后续阶段进行。

## 7. 队列和 pending Map 各解决什么

真实实现：C08 `request` 第 163 行；`sendRpc` 第 255 行；`receiveResponse` 第 285 行；`failPending` 第 294 行。解释性重写：

```javascript
let queue = Promise.resolve();

function request(input) {
  const timeoutMs = input.timeoutSeconds * 1000;
  const operation = queue.then(() => sendRpc("request", {
    clientApiVersion,
    codexTurnMetadata: input.codexMetadata,
    deadlineUnixMilliseconds: Date.now() + timeoutMs,
    request: input.request,
    requestType: input.requestType,
  }, timeoutMs));
  queue = operation.then(() => {}, () => {});
  return operation;
}
```

Promise 队列避免多个原生 request 同时改变界面。pending Map 则用 RPC id 将网络/管道响应归还对应 Promise。即使当前 request 串行，握手、错误、超时和连接关闭仍需要明确管理。

失败后的空 catch 只保证队列链不永久停在 rejected 状态；它不会把失败伪装成当前请求成功，调用者仍收到 operation 的拒绝。超时会清理并关闭连接，后续 client 会重新获取 transport。

## 8. 浏览器元素索引怎样对应真实节点

以下直接摘自 browser-service 的 B01；保留混淆局部变量和依赖 `Nr`：

```javascript
targetForElement(t, r) {
  let n = this.currentState(t),
      o = n.accessibilityRevision?.identityForElement(r),
      i = o == null ? void 0 : n.targets.get(o);
  if (i == null || i.javaScriptDialog != null && this.cdp.getJsDialog(t)?.id !== i.javaScriptDialog.dialogID)
    throw new Error(`Accessibility element ${r} is stale or missing`);
  if (n.documentKey !== Nr(n.mainFrameId, n.loaderId))
    throw new Error(`Accessibility element ${r} belongs to a previous page`);
  return {
    ...i,
    id: r,
    isValueSettable: n.accessibilityRevision?.isValueSettableForElement?.(r)
  };
}
```

链条是：**数字索引 → 当前 revision 中的 identity → targets Map → Frame/DOM 目标**。对话框和页面 loader 变化还会触发拒绝。这是复现时防止旧页面引用误击的关键。

B02 的 `buildAXCandidate` 在 `targets` 中保存 backendNodeId、frameId、loaderId、动作描述等；B03 调用各 Frame 的 `Accessibility.getFullAXTree` 并结合 DOMSnapshot 元数据。B04 说明 identity 查询通过 WASM revision 的导出函数完成。

## 9. 为什么 DOM-only 后端不能直接照搬 AX 点击

真实实现：C11，第 71–95 行。观察可 fallback，输入能力则单独检查。解释性重写：

```javascript
async function getState(tab, options) {
  if (tab.ax) return tab.ax.get("state", options);
  if (!tab.playwright?.domSnapshot) throw new Error("snapshot unavailable");
  return tab.playwright.domSnapshot();
}

function requireAXInput(tab) {
  if (!tab.ax) throw new Error("Use this tab's documented Playwright API");
  return tab.ax;
}
```

统一方法名不等于统一能力。DOM-only 的观察可能没有数字索引，必须改用该后端提供的 locator 接口。

## 10. 独立原型怎样对应这些机制

[mac-ax-bridge.swift](mac-ax-bridge.swift) 是本次独立编写并在本机编译通过的公共 API 原型。它对应原生端的“观察 → 引用 → 动作 → 截图”核心闭环，但没有复刻 Sky 原生源码。

关键入口：`AppSession.observe` 生成 AX 树与 revision，`resolve` 检查 revision / index / PID，`act` 使用 AXPress 或 AXValue，`screenshot` 使用 ScreenCaptureKit。它是单应用、单进程、JSONL 的最小服务。

编译通过和 `--self-test` 只验证可构建性与输入整数检查。该独立原型的 GUI、TCC、截图路径没有在本次实际运行；真实 GUI 成功证据来自正式 `cua_repl` 的计算器实验。两者的验证范围不能混合。

## 11. 提取和改名方法

`extract-core.cjs` 使用 Babel 解析/生成，导入别名按导入名称恢复，导出绑定按导出名称改名；关键模块的内部类、函数、WeakMap 槽位还配置了明确的作用域 rename。没有用字符串全局替换短变量名。

例如 C08 中 `E` 被阅读性命名为 `MacNativePipeTransport`，`P` 为 `decodeMessageFrames`，`b` 为 `encodeMessageFrame`；编译后的私有状态 WeakMap 被命名为 `apiVersionSlot`、`pendingSlot`、`queueSlot` 等。它们表达本次分析理解，不表示这些名字原本存在于作者 TypeScript 中。

纯格式化版的 AST 一致性更适合做可核验的原码对照；阅读版更适合理解；解释性重写更适合设计自己的实现。三者的角色在目录与注释中已分开。
