# Hanekawa

Hanekawa 是一个轻量、开源的自托管编程 agent，带 Electron 桌面应用。支持 Anthropic 与 OpenAI 兼容 API、会话持久化、自动上下文压缩、技能（skills）、子代理、MCP、钩子（hooks）、按权限放行的工具、图片输入、项目调度、内置浏览器和电脑操作。项目源码：[lyutianjian/Hanekawa-desktop](https://github.com/lyutianjian/Hanekawa-desktop)。

## 环境要求

- Node.js 24 及以上
- 桌面运行时固定为 Electron 45.2.1；macOS 13 及以上，Windows／macOS 使用 64 位系统
- npm
- 使用模型需要一个 Anthropic 或 OpenAI 兼容的 API Key；启动和配置本身不需要

## 安装与启动

```bash
npm install
npm run build:desktop
npm run start:desktop
```

Apple Silicon 安装包可从 [GitHub Releases](https://github.com/lyutianjian/Hanekawa-desktop/releases) 下载，打开 DMG 后将 Hanekawa 拖入 Applications。安装版自带 Electron／Node.js 运行时；Bash、Git、ripgrep 和外部 MCP 服务等工具仍需自行安装。当前预发布包使用 ad-hoc 签名，未做 Developer ID 签名与 Apple 公证，首次打开可能被 macOS Gatekeeper 阻止。

在 Apple Silicon Mac 上从源码构建 DMG：

```bash
npm ci
npm run dist:mac
```

产物位于 `release/Hanekawa-<版本>-arm64.dmg`。`npm run pack:mac` 只生成展开的 `.app`，用于安装版检查；两条命令都会先清理 `dist/`。图标源图在 `build/icon-source.png`，更换后在 macOS 运行 `npm run icons` 更新 ICNS。当前只提供 macOS arm64 打包配置。

`build:desktop` 用 `tsc` 编译主进程，用 esbuild 打包 preload 和渲染进程，再把渲染进程资源复制到 `dist/`。`start:desktop` 让 Electron 运行这份 `dist/`，所以改了源码要重新构建。

Windows 和 macOS 的关闭窗口按钮会隐藏窗口，正在执行的回合、后台任务和 MCP 连接继续保留。Windows 点击系统托盘图标恢复，macOS 点击 Dock 图标恢复；恢复的是原窗口和原会话。Windows 托盘不可用时会保留窗口并提示。结束应用请使用 Windows 托盘菜单的「退出 Hanekawa」或 macOS 菜单退出／⌘Q，应用会先停止会话、后台任务和 MCP；关闭会话面板、关闭项目仍遵循原来的清理规则，最后一个面板关闭后应用保留空窗口。

「设置 → 通用 → 运行时防止系统休眠」默认开启，选择全局保存，切换立即生效。开启时，Agent 回合（包括等待权限或回答）、独立上下文压缩，以及实际运行的后台 Bash／子代理会申请阻止闲置自动睡眠，允许熄屏和锁屏；关闭后立即释放请求。MCP 仅连接、Monitor 观察等待和协调者等调度不会单独阻止睡眠。未停止的后台开发服务器也算工作，长时间等待确认会增加耗电；隐藏时有待确认请求会尝试系统通知，通知被关闭时可恢复窗口处理。

「设置 → 通用 → 通知」控制 macOS／Windows 原生系统通知，选择全局保存在 `~/.hanekawa/settings.json` 并立即生效：

- **轮次完成通知**：从不／始终／窗口未聚焦时，默认「窗口未聚焦时」。正常完成的会话轮次发送通知，失败、停止、回滚及单独工具／内嵌子代理结束不发送完成通知。
- **启用权限通知**、**启用问题通知**：独立开关，默认开启。主窗口未聚焦且会话等待操作批准（包括计划模式确认）或问题回答时提醒；同一请求只提醒一次，多个待处理请求合并提醒。切到其他应用、最小化和隐藏窗口都算未聚焦。
- 点击通知恢复主窗口并定位相关会话；请求已经解决或关闭提醒开关后，待处理通知会关闭。系统拒绝通知时，开启的待处理提醒会尝试 Dock／任务栏提示，仍可恢复窗口处理。

macOS 的 Electron 45 通知使用系统 UNNotification API，需要应用签名；未签名开发宿主可能发送失败。Windows 需要带匹配 AppUserModelID 的开始菜单快捷方式，发行标识为 `com.hanekawa.desktop`，开发模式使用 Electron 可执行文件路径。Windows 安装包应注册对应的快捷方式与系统通知激活信息；当前仅配置 macOS arm64 安装包，尚未配置正式签名和 Windows 安装器。应用内开关不替代系统的通知权限，系统勿扰和通知设置仍然生效。

防休眠不拦截手动睡眠、合盖、关机或系统电源政策，也不唤醒已睡眠的电脑。Windows Modern Standby 在电池供电时限制电源请求，不能保证长任务持续执行；实际效果须在目标设备和供电模式下验证。系统恢复后应用按仍在执行的工作刷新请求，不自动重跑失败的回合。

Electron 偏好与 Chromium 数据固定在 `appData/hanekawa`（macOS 为 `~/Library/Application Support/hanekawa`，Windows 为 `%APPDATA%/hanekawa`），业务数据仍在 `~/.hanekawa`，保留已有迁移。发行构建前的 `npm run clean:dist` 只清理仓库的 `dist/`。开发模式下终端或开发宿主退出可能终止应用，不能代替安装版后台留存验收。

回合进行时，Claude Code 风格的动态标记、活动描述、计时和本轮输出 token 显示在当前的工作行中；工具组无论收起还是展开，动态标记、计时和计数均固定在组头状态行；展开后正在执行的工具用文字流光标识，已完成的工具恢复普通文字。思考状态行显示当前思考段的第一句话，默认收起；点击同一条状态行可在其下方展开或收起思考正文，不另外绘制上方的“思考过程”入口。工具结束后的请求空档保留在最后一个工具行，直到下一步接替，避免底部重复显示同一活动。没有对应步骤时，底部显示处理、输出、参数准备、重试或上下文压缩状态。计时从本轮开始，满两秒后显示；工具、思考、审批、提问及重试期间均保留计时和已有的 token 计数。工作行内部切换过滤 250 毫秒的短暂变化，工具描述至少保留两秒；审批、提问、失败和回合结束立即更新。回合结束直接收起动态状态，保留正常的回合统计；仍在运行的后台任务保留独立入口。

### 从旧名称升级

升级前请先退出旧版应用，避免两个版本同时写旧目录。首次启动会把这些旧位置迁到新名称，之后旧位置不再读取：

- `~/.myagent/` → `~/.hanekawa/`
- `~/Documents/myagent/` → `~/Documents/hanekawa/`
- Electron 的窗口位置、主题和侧栏宽度从旧的 `myagent` 配置目录复制到 `hanekawa`。

如果新旧目录同时存在，不会合并，旧目录保持原样（启动日志里会说明）。项目里的 `.myagent/` 不会自动迁移，需要手动 `mv .myagent .hanekawa`；旧调度线程的 worktree 会留在 `~/.myagent-worktrees/` 直到线程结束。环境变量从 `MYAGENT_*` 改为 `HANEKAWA_*`，旧名不再生效。旧会话里已经写进对话的绝对路径（例如超长工具输出的临时文件路径）不会改写，回看时可能指向旧位置。

## 配置

### 模型与服务商

没有可用的默认模型时，应用启动后会自动打开 **模型与服务商** 配置页，并弹出添加服务商的窗口。可以先关掉它浏览会话和历史，之后从 **配置模型** 入口重新打开。

配置页只列服务商（名称、协议、模型数）。点「添加服务商」先选一个预设，再在同一个窗口里填名称、API 协议、API Key、Base URL，并在下方的模型表格里添加模型：「获取模型列表」从服务商拉取可选模型，勾选即加入表格，也可以「添加模型」手动填写模型 ID。新服务商至少要有一个模型。展开模型行可以设置「支持扩展思考」「支持图片输入」、上下文长度、最大输出 Token、每个思考档位是否支持，以及可折叠的「价格」。显示名就是模型在配置里的键名，不填时用模型 ID；与别的服务商下的模型同名时需要填一个不同的显示名。改服务商名或显示名会同步更新引用它的路由。一次「保存」提交整个窗口的改动。

默认模型在「路由」卡顶部选择；未选默认模型时，第一个保存成功、可解析的模型会成为默认模型。手写配置里没有归属到已配置服务商的模型，列在「未归属服务商的模型」一行里，只能编辑模型本身。配置无需重启即可生效：所有已打开的项目都会收到全局服务商变更，正在运行的回合结束后才替换运行时。删掉最后一个模型会让应用回到待配置状态。配置完成前尝试发送的消息会保留草稿和附件。

应用会创建并保存 `~/.hanekawa/config.json`，所有项目共用。缺少模型、模型引用失效或服务商配置不完整时，配置入口始终可用。启动时不测试网络连通性或远端鉴权，请求出错会在使用模型时报告。

也可以手动编辑 `~/.hanekawa/config.json`：

```json
{
  "models": {
    "claude": {
      "provider": "anthropic",
      "model": "claude-sonnet-4-20250514",
      "apiKey": "sk-ant-..."
    },
    "openai-compatible": {
      "provider": "openai",
      "model": "deepseek-chat",
      "apiKey": "sk-...",
      "baseUrl": "https://api.deepseek.com/v1"
    }
  },
  "defaultModel": "claude",
  "fallbackModel": "openai-compatible",
  "agent": {
    "system": "You are Hanekawa, a desktop programming assistant."
  }
}
```

`provider` 有三种：`anthropic`（Anthropic Messages）、`openai`（OpenAI Chat Completions，各家兼容服务通用）和 `openai-responses`（OpenAI Responses，OpenAI 官方推荐；GPT-6 Astra、GPT-6.1 Sol 只能在 Responses 下调用工具）。

`config.json` 只有全局一份。项目和本地 settings 中的 `models`、`endpoints`、`routing`、`defaultModel`、`fallbackModel`、`compactModel` 及 `agent.*` 会被忽略，不能借用全局服务商凭证或写入全局配置。旧的用户层 `~/.hanekawa/settings.json` 仍兼容这些字段，`config.json` 优先。

项目里的 `.hanekawa/config.json` 不会自动导入或归档，应用会提示并保留原文件。确需导入时，请亲自审阅服务商地址、模型覆盖和凭证，先备份 `~/.hanekawa/config.json`（例如复制为 `config.before-import.json`），再手动把确认可信的字段合入全局配置并重新加载。仅有本地文件或未被 Git 跟踪，不能证明它来自你本人。

### 设置文件的层级

权限、MCP、钩子、技能开关等设置分三层，按顺序合并：

| 层 | 位置 | 说明 |
|---|---|---|
| 用户 | `~/.hanekawa/settings.json` | 对所有项目生效 |
| 项目 | `<项目>/.hanekawa/settings.json` | 随仓库共享；其中的 `permissions.mode` 和 `mcp.trustedServers` 会被忽略并给出提示 |
| 本地 | `~/.hanekawa/projects/<key>/settings.local.json` | 个人的每项目设置，不放在项目目录里 |

权限规则、钩子等按层拼接，MCP 信任取并集；`skills.disabled` 例外，按层整体替换。

`thinking`（扩展思考）和 `cache.ttl1h`（1 小时提示词缓存）只认用户层：设置页「通用」写的是 `~/.hanekawa/settings.json`，项目和本地层里遗留的值会被忽略。

`config.json` 和这三层设置文件只有在不存在时才按空配置初始化；已有文件的 JSON 损坏、顶层不是对象或无法读取时，会报告路径并停止加载或保存，不会自动覆盖或重建。运行中重新加载失败会保留上次有效的内存配置。请先备份原文件，再修正内容或访问权限并重新加载；首次启动失败时，修正后重新启动应用。

多个项目同时修改全局 `config.json` 时，过期的配置副本会拒绝保存，并提示重新加载。请加载最新配置后重新应用本次修改，以免覆盖另一个项目刚保存的设置。

项目里的 `.hanekawa/` 只存放你手动放进去的共享配置（设置、技能、agent 定义、规则、MCP）。会话及其他运行时数据（溢出的工具输出、图片附件、计划文件）以及个人的每项目设置（`settings.local.json`、`agents.local/`）都在 `~/.hanekawa/projects/<key>/` 下，`<key>` 由项目路径推导，所以应用自己写的东西永远不会出现在项目里。重命名或移动项目会得到新 key 和空历史，旧历史留在旧 key 下。如果项目的 `.hanekawa/` 里还留着会话或本地设置（例如从旧的 `.myagent/` 手动改名过来），下次打开时会被迁走：每个文件先复制、校验，再删除原件；清空的 `.hanekawa/` 会被删除；搬不走的保持原样，并在启动时警告。

### 指令文件

Hanekawa 每次请求都会把指令文件放在对话开头的一条 `<system-reminder>` 里（和记忆索引在一起），而不是系统提示：仓库里的指令文件是用户层面的内容，不该拿到 harness 规则的权威。

1. `~/.hanekawa/AGENTS.md`：你对所有项目的个人指令，可在设置的「个性化 › 自定义指令」里编辑。系统提示总会写明这个文件的位置（为空时也写），你让模型改它时，它可以直接改：主对话中，在 `default`、`auto`、`bypass` 模式下读、写、编辑这个文件都不弹询问；plan 模式和只读模式照常拒绝，删除照常询问，子代理照常走权限判定；这个文件本身是符号链接时不豁免。deny 规则照样生效，ask 规则照样询问（`bypass` 除外）。
2. 从工作目录向上走到文件系统根目录，每一级取 `CLAUDE.md`，没有时用 `AGENTS.md`。

每一级目录只取两个指令文件中的**一个**：同时维护 `AGENTS.md` 和 `CLAUDE.md` 的仓库，否则每次请求都会重复发送同一份指南。文件按从外到内读取，越近的越靠后、优先级越高。

这些文件在项目打开时读一次，会话运行时构建时固定下来，和钩子一样。会话中途修改它们，会在下次重新加载设置时生效——在设置页保存任意内容就会触发一次，指令变了就重建运行时。例外是 `~/.hanekawa/AGENTS.md`：每个会话开始时（新会话、`/clear`、`/resume`）各读一次，所以无论是模型改的、在「自定义指令」里保存的还是你在编辑器里改的，下一个新会话就能看到；已打开的会话保持开始时那一份，重新加载设置也不变。

### 自动记忆

模型可以记下跨会话保留的笔记：你的纠正和偏好、代码里看不出的项目背景、外部资料的位置。它们是普通 Markdown 文件，存放在 `~/.hanekawa/projects/<key>/memory/`（每个工作目录一份，主目录单独一份），每个文件带一小段 frontmatter，另有索引 `MEMORY.md`，每条笔记一行。可以用任何编辑器打开或修改，也可以让模型忘掉某条。

- **加载**：会话运行时首次构建时读取索引，放进对话开头那条指令 `<system-reminder>`（记忆的用法说明在系统提示里）；`/clear` 和 `/resume` 会重新读取，切换模型或重载设置不会。会话中途写下的笔记在下一个会话可见。索引截断在 200 行或 25,000 字节。
- **审批**：主对话中，直接读写、删除记忆目录里的 `*.md` 在任何权限模式下（包括 plan）都不弹询问。deny 规则照样生效，ask 规则照样询问（`bypass` 除外）。该目录也算工作区，所以对它执行只读 shell 命令（`ls`、`cat`、`grep`）无需询问；在里面写入或删除的 shell 命令照常询问。
- **开关**：设置里写 `"autoMemory": false`，之后打开的会话就不再启用：没有提示段、没有审批豁免、不创建目录。已有笔记保留。
- **不覆盖的范围**：子代理既看不到也不使用记忆；记忆文件不参与 `/rewind`。在桌面端移除项目会连同其他数据一起删除它的记忆。

### 路由

`routing` 把特定角色交给特定模型。每个值是 `models` 中的 key，或 `"inherit"`（跟随主循环的模型）：

```json
{
  "routing": {
    "main": "inherit",
    "plan": "claude",
    "compact": "openai-compatible",
    "subagent": {
      "general": "inherit",
      "explore": "openai-compatible"
    }
  }
}
```

没有单独配置的 `subagent` 类型回落到 `subagent.general`，再回落到 `inherit`。所有项默认 `inherit`，所以单模型配置完全不需要 `routing`。

> **不兼容变更。** `fast` / `balanced` / `powerful` 档位以及把它们映射到模型的 `profiles` 层已经删除，`routing` 直接写模型 key。仍在使用旧写法的配置可以正常启动并打印警告：写成档位的 `routing` 项按 `"inherit"` 处理，`defaultModel` 写成档位时回落到第一个可解析的模型。随档位一起消失的还有两个行为——plan 模式不再自动升级模型，压缩不再自动降级模型。需要的话用 `routing.plan` / `routing.compact`（或独立的 `compactModel`）设回来。

### 扩展思考

扩展思考默认开启：请求携带服务商的自适应思考配置，`/effort <low|medium|high|xhigh|max>` 调整模型投入多少思考。

Anthropic 回复中的签名思考只会回传给产生它的同一模型和服务地址。新回复会保存不含 API Key 的来源标记；切换来源或继续没有来源标记的旧聊天时，请求省略无法确认来源的签名思考，正文和工具记录保留，旧聊天文件不改写。仅更换 API Key 不改变来源。

并非每个模型都支持每个等级，有些端点遇到不支持的等级会直接拒绝而不是向下取整。`supportedEfforts` 列出模型接受的等级——对应设置页服务商窗口里每个模型的「思考档位」开关，不填表示五个都支持。集合外的等级在选择器里显示为不可用，并降到下方最近的受支持等级：

```json
"models": {
  "big": { "provider": "anthropic", "model": "claude-opus-5", "supportedEfforts": ["low", "high"] }
}
```

设置页「通用 › 扩展思考」关闭后，请求不再携带 `thinking` 参数；开关写进项目的 `settings.local.json`，并重建当前会话的运行时。它在构建运行时时读取，因此也覆盖子代理。

单个模型可以单独关掉：服务商窗口里模型的「支持扩展思考」开关，即模型配置上的 `"thinking": {"type": "disabled"}`。关掉的模型不论全局开关如何都不带思考参数；重新打开时，手写的 `thinking` 预算会保留。

```json
{ "thinking": false }
```

### 模型上下文窗口

服务商支持的上下文窗口不是默认的 272,000 token 时，在模型上显式设置 `contextWindow`：

```json
{
  "models": {
    "mimo-v2.5": {
      "endpoint": "xiaomi",
      "model": "mimo-v2.5",
      "contextWindow": 1000000
    }
  }
}
```

不填时先回落到 `agent.contextManagement.contextWindow`，再回落到 272,000。这个值决定上下文预算、历史选择、压缩阈值、ToolSearch 阈值和状态显示；Hanekawa 不会根据模型名推断它。

设置页所有手动填写的 token 数量（上下文窗口、模型上下文长度、最大输出 Token、摘要输出上限、手动压缩预留）均支持 K/M 后缀，不区分大小写，也支持小数：`32k` = 32,000，`1.5k` = 1,500，`1m` = 1,000,000；整数输入仍然有效，保存时自动换算为数值。

输入框旁的模型选择器显示模型名和当前思考强度。点击后用带刻度的滑杆调整强度，松手时保存并保持卡片打开，便于继续调整；滑杆只包含当前模型支持的档位。点击卡片中的模型名可切换到模型列表，勾号标出当前模型，返回按钮或 Escape 回到强度卡片。浮层开合和页面切换带短暂过渡，并遵循系统的减少动态效果设置。`/model` 与 `/effort` 仍打开原有选择面板。

### 模型价格

模型行的「价格」里填每百万 token 的单价：输入、输出、缓存写入、缓存命中，币种 USD 或 CNY，对应配置里的 `pricing`（`inputPerMillionTokens`、`outputPerMillionTokens`、`cacheWriteInputPerMillionTokens`、`cacheReadInputPerMillionTokens`、`currency`）。四项都空表示不计价；填了任何一项就必须填输入和输出；缓存两项留空时按输入单价计。

每次请求返回时按实际服务它的模型计价——主对话、备用模型、压缩、子代理各按各的价格——再累加到会话开销；之后改价格不影响已经算过的部分，不同币种分开累计。开销随用量写进会话的 metrics 文件，重新打开会话时恢复。输入框下方用量读数的悬停卡片里显示「会话开销」，`/cost` 读同一个数；用到未设置价格的模型时注明未计入，早于开销记录的旧会话注明不含早期请求。

失败、取消或重试之前已经返回的用量也会入账，子代理和晚完成的摘要按各自请求计入所属会话。请求没有返回完整用量时，悬停卡片和 `/cost` 会说明 token 与开销可能不完整；完全没有设置价格的会话也会显示缺价提示。未保存的历史消耗无法从当前价格精确补算。

全局「总 token」包含主对话、压缩、子代理、标题与工具摘要，会话累计与全局使用同一份请求用量。旧版全局统计升级时先备份 `~/.hanekawa/usage-history.json` 到 `usage-history.json.v1.bak`，再合并应用改名前后的重复会话并重算仍有 metrics 的历史；已删除会话保留的统计继续保留。

- 权限页右上角可以选择「个人」或具体项目，不显示「最近」；「最近」按个人范围处理。「个人」就是全局规则，所有项目通用；选择项目后，只能编辑该项目本地的规则。权限规则跨层**拼接**，项目范围中继承的个人规则和仓库规则以只读方式列出，可切回「个人」编辑全局规则。默认权限模式在个人范围设置。
- MCP 信任取**并集**，页面只能修改项目本地的信任；在 `~/.hanekawa/settings.json` 授予的 MCP 信任要去那个文件里删。
- 「技能和 MCP」是两个横向标签页，技能在前、MCP 在后，标签上带数量；搜索框会同时过滤两页并显示命中数。技能行在悬停时显示圆角底色，点击打开详情弹窗：顶部可以启停技能，中间显示渲染后的完整 `SKILL.md`，来源、加载方式与风险提示收在「技能信息」中，底部可以「打开」「在 Finder 中显示」「复制 Markdown」，Hanekawa 管理的技能还有「卸载」。点击遮罩、关闭按钮或按 Esc 返回列表，原搜索与滚动位置保留。带 hooks 的技能导入后默认关闭，读过详情再打开。
- 技能页右上角可以选择项目，查看该项目可用的项目技能与个人技能。点击项目旁的 × 取消选择后显示「个人」，只管理个人技能；开关写入全局默认，已打开的项目同步重新加载。项目已有的独立开关设置保持优先。个人范围中的文件操作和卸载指向个人副本，即使项目里有同名技能也不会改动它。
- 六个上下文管理数值在项目启动时读取一次，修改后重启生效。
- 默认权限模式只影响之后新开的会话；线程调度的六项设置存在全局配置里，所有项目共用，跟随全局的协调者或线程在下一回合采用新值，会话里手动指定的模型和思考强度不被覆盖。其余设置立即作用于已打开的会话。

## 使用

### 界面与快捷键

左侧是侧栏：会话搜索、按项目分组的会话列表、「最近」（不属于任何项目的会话）以及「项目」入口，宽度可拖动。右侧面板由标题栏右端的图标按钮切换，每个按钮一页，再点当前页的按钮收起面板：**任务**（计划保持独立；后台命令和子代理混排在「运行中／已完成」两组，已完成默认收起，分组记住展开选择；右上垃圾桶仅隐藏当前会话点击时已完成的任务，不删除任务或输出，新完成项仍会出现，重启应用后恢复；顶部独立显示「后台任务」标题，任务之间用细线分隔；后台命令收起时为统一高度的单行标题，优先显示 description，没有描述时显示命令并省略超出部分；子代理第二行保留模型和累计 token，点击查看对话；后台命令展开后以描边框显示高亮的完整命令，以独立灰底区域显示输出，并显示状态和耗时；运行项右侧常显停止按钮，已结束的任务显示详情箭头，失败项在标题右侧单独显示红色「失败」标签；有内容在运行时按钮上显示圆点）、**线程**（仅项目调度的协调者和线程会话中出现）、**改动**（本会话各编辑工具改过的文件，同一文件多轮修改按顺序列出）、**文件**（目录浏览、预览和直接编辑）、**浏览器**。各页分别记忆宽度，双击拖柄恢复默认宽度。

子代理预览显示模型和累计 token，不显示时间；详情页显示状态、模型和实际耗时，运行时计时，结束后固定。子代理和调度线程的详情页共用对话布局：顶部信息固定，对话单独滚动，运行反馈显示在对话底部。线程的初始任务、后续调度消息和回复按顺序显示在对话中。

空会话的首页可以切换 git 分支（「切换分支」），并显示用量卡片（概览/模型，全部 / 30 天 / 7 天）。概览展示总 token、会话数、活跃天数与每日活动热力图；模型用量以紧凑表格显示模型名、token 和占比，列表独立滚动，顶部筛选与摘要保持可见。会话标题栏可以重命名、删除会话，或「在 VS Code 中打开」项目。

「最近」中的会话共享 `~/Documents/hanekawa` 作为工作目录，打开时自动创建。相对路径的文件写入、Bash 命令和「在 VS Code 中打开」都从这个目录开始，首页不显示工作区目录按钮。从旧版本升级时，`~/Documents/myagent` 会自动改名为 `~/Documents/hanekawa`，之前生成的文件跟着目录一起移动；旧会话重新打开后同样使用这个目录，历史、记忆和配置仍在原来的存储位置。

### 动效与阅读

菜单、详情、侧栏和权限卡片使用柔和可见的动效。打开和关闭是连续的，中途反向操作会从当前位置继续。流式输出时文本保持可读。批准或拒绝请求立即生效，焦点回到输入框，卡片随后收起。

思考过程和工具详情均默认折叠；手动展开/折叠按会话在当前窗口内记住，不跨重启保存。思考标题显示该段的第一句话，空内容显示「思考过程」；可展开的工具项和工具汇总行始终显示箭头，思考的箭头在悬停或键盘聚焦时显示。回合结束不改手动选择，键盘焦点、文本选择以及向上翻阅仍会被保护；阅读较早的消息时，新输出不会把你拉回底部，「回到最新」可立即跳回。恢复会话时直接显示已保存内容，不重放工具完成动画。

桌面端遵循系统的**减弱动态效果**偏好（包括应用运行中修改）：移动、缩放和循环效果停止，进行中的过渡直接落定，状态文字和控件仍然可用。

### 会话引用

在当前会话引用其他会话有四种方式：从侧边栏拖入；右键会话选择「复制会话链接」后粘贴；输入 `@关键词` 选择会话；直接让 agent 查找之前讨论某件事的会话。引用以「气泡图标 + 标题」显示在句子里，点击可打开来源；输入中的引用可整体删除，复制后仍是可重新识别的链接。

`@` 候选同时列出会话标题、文件夹和支持的文本/图片文件。文件显示类型图标、文件名和相对父目录；带 `/` 的路径查询继续导航目录。选择候选只插入，下一次 Enter 才发送。

引用只携带会话身份，不自动加载历史。agent 使用正式只读工具 `ReadSession` 搜索或分页读取；搜索和读取都显示在对话的工具记录中，展开可查看实际结果。标题搜索无结果时可按正文关键词搜索，返回命中片段后再读取附近内容；正文使用字面关键词匹配。范围包括本机已登记、当前打开的项目及「最近」，来源项目无需打开，来源会话不会因此运行或新增消息。来源已删除时会明确报错。

读取默认从最近内容开始，可继续读更早历史或按需读取工具细节；每次只返回当时已保存的内容，遵守现有工具权限规则并脱敏。应用内链接格式为 `hanekawa://session/<完整 UUID>`，不包含文件路径；本期支持应用内复制、粘贴与打开，不包含外部应用唤起或跨设备分享。

## 图片输入

只有你为某个模型打开图片输入后，它才会收到图片：在 `config.json` 的模型上设置 `supportsImageInput: true`，或在设置页服务商窗口里展开该模型、打开「支持图片输入」。默认关闭，不会根据模型名或端点推断，同一端点下的两个模型可以不同。这个开关是声明而非探测：端点若拒绝图片内容，会返回它自己的错误，Hanekawa 会连同下一步该怎么做一起显示。

支持 PNG、JPEG、GIF 和 WebP。真实格式从字节判断，扩展名写错也没关系；会应用 EXIF 方向；动图 GIF 和 WebP 取第一帧；SVG 保留文本语义。BMP、HEIC、TIFF、AVIF 会被拒绝，并提示先转成 PNG 或 JPEG。`Read` 工具按同样的规则把图片文件发给模型，并标注原始尺寸和发送尺寸。

在输入框里粘贴图片、把图片拖进对话区，或从 `+` 菜单选「选择图片」即可附加，每次输入最多 10 张（显式附件和 `@` 引用的图片合计），消息可以只有图片。每张图片显示一个缩略图，点击后在应用内全屏查看，可放大缩小。

拖进对话区的其他文件和文件夹只附上路径：输入框里每项显示一个方块（完整路径，左下角标格式或「文件夹」），发送后模型按需自行读取，项目外的路径照常经过权限确认。

每张图片先存储，再发送规范化的副本：按 EXIF 旋转、统一颜色、去除元数据、长边缩到 2,000 px（不放大），然后压缩——优先 PNG 以保持文字和透明度清晰，大截图用 JPEG——每张不超过 3.75 MB。原始输入超过 20 MB 或 4000 万像素会被拒绝，压到最低质量仍超出预算的也会被拒绝，错误信息会说明原因并建议裁剪。

当前模型不支持图片时，发送**新**图片会在回合开始前被拦下——草稿保留，提示指向 `/model`。对话中已有的图片变成带文件路径的文字占位符，每次切换只提示一次，而不是每步一次。原图仍保存在会话里，切回支持图片的模型会再次发送。压缩时图片总是被总结成文字（压缩模型不需要支持图片），但保留最新一条用户消息的图片；被压缩的图片可以从缓存路径重新读取。单次请求最多携带 100 张图片，优先丢弃最旧的历史图片；当前输入的图片不会被悄悄丢弃。

附件存放在 `~/.hanekawa/projects/<key>/attachments/<session-id>/`。导入时复制图片——无论发送、移除草稿附件还是删除会话，都不会修改或删除你的源文件。删除会话会删除它存储的附件；关闭面板或重启会保留；不再被引用的文件在 24 小时保留期过后清理。

### 文件浏览与编辑

标题栏的文件夹按钮打开右侧「文件」面板：左边预览／编辑，右边目录树。面板和目录树可调整宽度，目录树可以收起，文件面板可以放大。每个会话保留自己的文件标签、光标、撤销记录和未保存内容；线程使用自己的 worktree，「最近」使用 `~/Documents/hanekawa`。

- 目录按需展开，包括隐藏文件、空目录和被 Git 忽略的文件。名称／相对路径筛选可以找到未展开的文件；默认跳过 `.git`、`node_modules`、构建输出等目录，选中该目录后可在其内部筛选。最多显示 500 个匹配。
- 文本、代码和 Markdown 使用 CodeMirror 编辑，支持查找／替换、撤销和缩进。Markdown 默认预览，可切换源码；工作目录内的相对链接和图片可直接打开，远程图片不自动加载。HTML 仅作为源码显示。
- 停止输入约 700ms 后自动保存，中文输入组合结束后开始计时；`⌘S / Ctrl+S` 立即保存。保存保持原有 UTF-8／UTF-16LE 编码、BOM、换行方式和文件权限。文本上限为 5 MiB；二进制、未知编码和超限文件提供外部打开入口。
- 无本地改动的文本会自动加载外部修改；有改动时暂停自动保存并提示冲突，可查看差异、采用磁盘版本或明确覆盖。外部删除不会自动重建文件。保存失败时保留编辑内容并可重试。
- PNG、JPEG、WebP、GIF、SVG 提供只读预览与缩放；PDF 提供离线翻页和缩放，图片／PDF 上限为 50 MiB。密码保护、损坏和不支持的文件可在外部应用打开。Office 预览／编辑、文件新建／删除／重命名不在首版范围内。
- 切换文件／会话、收起面板会立即尝试保存；关闭标签／会话或明确退出前检查未保存内容，失败时可取消操作。普通关窗仍按原有规则隐藏应用。缓冲仅在内存中，崩溃或强制结束后无法恢复尚未保存的输入。

文件操作限制在当前会话的实际工作目录内，目录外符号链接不能进入。手工编辑直接写回文件，不经过 Agent 工具审批，不产生工具记录或 token 消耗，也不加入 Agent 的文件历史；`/rewind` 恢复 Agent 已追踪的同一文件时，仍可能覆盖之后的手工修改。

### 内置浏览器

桌面端带一个真实的浏览器，agent 操作、你在旁观看。通过「视图 → 显示 / 隐藏浏览器」或标题栏右端的按钮打开；它占据窗口右侧面板，有自己的标签栏、后退/前进/刷新、地址栏和「＋」新建标签页，页面出错时显示可「重试」的错误页。标签页属于打开它的会话通道——切换项目时标签页跟着切换——关闭通道会关闭它的页面。

agent 通过 `Browser` 工具使用同一组标签页：打开、导航、后退/前进/刷新；把页面读成可操作元素表或纯文本；截图；点击（含按坐标点击）、悬停、输入、按键组合、滚动、选择原生 `<select>` 选项、勾选复选框；等待元素或网络空闲；模拟 iPhone、iPad、桌面等设备尺寸做响应式测试；还能在一次调用里批量执行多个步骤。与 `WebFetch` 不同，JavaScript 会运行，登录状态在多次调用间保留，模型读到的是渲染后的页面而不是 HTML 源码。导航按主机名请求你的许可，和 `WebFetch` 一样。只打开 `http`/`https` 地址，`file://` 一律拒绝；本地页面用 `path` 打开——应用自己用回环 http 把文件提供给页面，相对 CSS、脚本和图片照常加载，工作区外的路径会先问你。`~/.hanekawa` 下的数据（含 API Key）永不提供。下载被禁止。页面自己在 console 里报的 JavaScript 错误会附在下一次读取中（标签列表、元素表、正文、截图都算），每条只报一次——点击看起来没反应时，通常就是它在报错。

页面在独立的持久会话分区中加载，cookie 与应用本身隔离；页面接触不到 Hanekawa 的任何东西：没有 preload 脚本、没有 Node 集成、沙箱化且上下文隔离，自动化操作也限定在自己的隔离环境里。密码、一次性验证码和银行卡字段永远不会投射给模型——它们的文本和值返回为空——agent 在这类字段里输入的内容也不会回显到对话记录中。JavaScript 对话框不会真正弹出：`alert` 立即返回、`confirm` 得到 false、`prompt` 得到 null，页面不会因为等一个没人点得到的对话框而卡住。地址里带用户名或密码的 URL 一律拒绝打开——凭据会跟着地址进入标签栏和对话记录，登录应该在页面上做。

你可以随时接管标签页：在 agent 的回合进行中，点击地址栏旁的「接管」，或直接在页面里点击、键入（滚轮只算浏览，不算接管）。agent 的下一次浏览器调用会失败，并被要求停下来问你想怎么做；在你交还之前它一直被拦着。交还有两种方式：点击「交还」按钮，或给 agent 发一条消息；回合结束也会自动解除。回合之外，标签页随你使用，不算接管，只是 agent 上次读到的页面快照会失效。

### 项目调度

从侧栏的「项目调度」入口打开调度页，可以「新建调度」（选择一个文件夹），每个项目一张卡片，点开进入该项目的**协调者**：每个项目一个长期存在的会话。新协调者不会自动行动；项目还没有线程时，欢迎语里有「读取项目」按钮，点击后派一个只读线程阅读项目并给出几条建议。协调者只读加调度（权限模式锁定为 `readonly`）：它能阅读和搜索代码，并启动、发消息给、停止、完成**线程**——线程是干活的普通会话。线程默认 `auto` 权限模式，不能再启动线程。需要写代码的线程有自己的 git worktree，位于 `~/.hanekawa-worktrees/<key>/<threadId>`，分支 `hanekawa/<slug>-<threadId>`；只读线程共用项目目录。

- **侧栏**：顶部的「项目」区为每个项目显示一行协调者，带「N 运行中 · N 需要你」计数；线程本身不在侧栏列出。
- **线程视图**：标题栏显示「← 协调 · 线程名 [状态] [停止]」。右侧「线程」页顶部显示线程计数和「全部停止」，标题栏的「线程」按钮带阻塞线程数角标。线程列表按阻塞、运行中、空闲、安静、已完成分组（后两组默认折叠），每个线程一行，有新动静未查看的显示圆点；行尾「⋯」菜单可在主画布打开、停止或「标为完成」。
- **汇报**：线程的回合结束时，一份简短的、经过清理的笔记（是数据，不是指令）以卡片形式出现在协调者对话里。每个线程汇报后协调者都会被唤醒（其他线程仍在运行时它只处理已汇报的部分）；线程用 `AskCoordinator` 提问也会立即唤醒它。你上次在协调者里发言后，最多自动唤醒 20 次。权限请求从不转给模型：等待审批的线程显示为「需要你」并发出桌面通知。
- **合并**：线程的输入框上方显示「项目名 分支名 +N −M [合并] ×」；协调者显示「N 个线程分支待合并」，可展开。合并由应用自己运行 `git merge`。主工作区有未提交改动时拒绝合并；有冲突时中止合并并显示「有冲突 [让线程解决]」，让线程更新自己的分支。合并成功后删除 worktree 和分支，并把线程标记为完成。
- **长会话**：协调者会收到线程状态看板的快照，并使用专门的压缩提示；压缩后恢复最新看板。空闲超过缓存 TTL 且上下文用量超过 40% 时会提前压缩；如果压缩持续失败，会用摘要和看板开一个新的协调者会话。
- **设置**：「模型与服务商」页的「线程调度」分组设置协调者和线程的模型与思考等级，以及「安静天数」（默认 3）和「自动结案天数」（默认 7），空闲线程超过这些天数后分别标记为安静或完成，填 0 关闭。这六项保存在全局配置里，所有项目共用；「跟随全局主模型」表示使用全局主模型，不继承某个会话的临时选择。会话里手动换过模型的线程保留自己的选择，重开或重启后仍然有效，换回「跟随」只影响这一个会话。被重启打断的线程会被标记，不会自动恢复。旧版本按项目保存的这六项会在启动时迁移到全局配置：只有一个值就直接采用，多个项目取值不同时不会替你选，错误提示会显示在「线程调度」卡片里，等你在页面上选定。

### 撤回（`/rewind`）

`/rewind` 回到较早的一条提示，可以恢复对话、代码或两者。桌面端先在「操作范围」选择恢复范围或摘要方向，再点击「确认回退」或「确认摘要」；切换范围只更新说明，不会立即执行。数字键只选择范围；也可用方向键选择、Tab 移至确认按钮后按 Enter 执行，Esc 返回检查点列表。

恢复对话时，所选提示及图片会回到输入框一次；如果它来自排队消息，也不会自动重发。其他尚未发送的排队消息会保留原顺序、优先级和图片；摘要回退同样保留待发送队列。

恢复代码只恢复 **agent 的写入工具改过的文件**（`Edit`、`Write`、`MultiEdit`、`NotebookEdit`、`Delete`）。每次这类写入之前，原内容会被复制到 `~/.hanekawa/file-history/<session-id>/`，撤回时把这些副本放回去——并删除 agent 在所选位置之后新建的文件。

`Bash` 只在命令文本能明确看出目标时才被覆盖：输出重定向（`> f`、`>> f`、`2> f`、`&> f`）、`tee`，以及非递归的 `cp`/`mv`。用变量、通配符或命令替换拼出目标的命令，以及脚本间接写入的任何内容，都不会被捕获。

其他一切保持原样：你在编辑器里的修改、构建产物、`git` 操作都不会被捕获，也不会被回滚。撤回撤销的是 agent 的编辑，不是你工作区的状态。

## 权限

每次工具调用先由风险分级器（`src/harness/risk/`）定级，再由权限闸门把等级与你的规则和会话模式结合起来判断。

全局 `~/.hanekawa/` 可以读取、搜索和编辑，不再按目录整体封锁。读取普通全局文件无需询问，协调者和只读子代理也可读取；写入仍遵守权限模式，修改 `config.json` 等权限配置仍按 `critical` 处理，deny 规则照常生效。从主目录做宽泛搜索时仍跳过项目运行数据，明确指定会话或数据目录即可搜索。

模型收到的工具结果（包括 Read、Grep、Bash、后台通知和子代理结果）会把已加载配置中的 API 密钥及 JSON `apiKey` 字段替换为 `[REDACTED]`，模型 key、服务地址等普通配置保持可见。应用发请求时仍使用真实密钥。全局 `config.json` 和兼容的 `settings.json` 可按脱敏视图编辑；Edit、MultiEdit、Write 保存时恢复原位置的密钥，整文件覆盖时也会保留仍存在的端点／模型中省略的密钥。新增或改名后无法对应的占位符会拒绝保存，请在设置页配置对应密钥。这是正常文本输出的脱敏，不是对任意脚本编码、拆分密钥行为的凭据隔离。

| 等级 | 含义 |
|---|---|
| `readonly` | 不做任何修改，只读工作区 |
| `normal` | 普通的编辑、构建、安装、联网、读取工作区外的文件 |
| `risky` | 不可逆或影响范围大但属于常规操作：`git push --force`、`git reset --hard`、`rm -r`、发布、`sudo`、写工作区外的文件、`.env` |
| `critical` | 破坏性或持久性的操作：`rm -rf ~`、`mkfs`、`curl … \| sh`、私钥和云凭据、shell rc / `authorized_keys` / git hooks、Hanekawa 自己的权限配置 |

| 等级 | `default` | `plan` | `auto`（需要时询问） | `bypass` |
|---|---|---|---|---|
| readonly | 允许 | 允许 | 允许 | 允许 |
| normal | 询问 | 拒绝写文件（会话计划文件除外）；单纯读取工作区外文件直接允许；其余询问 | 允许 | 允许 |
| risky | 询问 | 同 normal | 询问 | 允许，并提醒模型 |
| critical | 询问，不记住 | 拒绝 | 询问，不记住 | 大范围删除拒绝，其余允许并提醒模型 |

输入框上的权限按钮点开后可在 `default`、`plan`、`auto`、`bypass` 之间选择（协调者会话里不显示）。`readonly` 是内部模式，用于内置的 explore/plan 子代理和协调者会话。子代理的权限永远不会比父会话更宽松。旧的 `acceptEdits` 模式现在就是 `auto`，已有设置和 agent frontmatter 会自动迁移。

规则按优先级：

1. `deny` 规则在任何模式下都拒绝，永远不会变成询问。
2. `ask` 规则询问；`bypass` 忽略它。
3. `allow` 规则覆盖 `normal`；只有规则文本本身就是 risky 的（`Bash(git push --force:*)`、`Edit(/etc/hosts)`）才覆盖 `risky`，`Bash(git push:*)` 不算。没有规则能覆盖 `critical`。

`bypass` 信任模型，唯一的防护是大范围删除——删除 `/`、主目录、两者的直接子目录、盘符根目录或工作区根目录，或者目标在运行时才确定的递归删除（`rm -rf "$X"`、`xargs rm -rf`、`cd "$X"` 之后的相对路径）。`$HOME`、`$PWD` 和 `$(pwd)` 会先解析再判断。需要带护栏的模式请用 `auto`。

「始终允许」只对 `normal` 持久保存。`risky` 可以在本会话内按精确的命令或路径允许。`critical` 两者都不提供。

文件规则匹配解析后的绝对路径。以 `/` 或 `~` 开头的模式是绝对路径，其他都相对于项目根目录，所以 `Read(.env)` 只匹配根目录的 `.env`——要匹配所有的请写 `Read(**/.env)`。`Read`/`Edit` 的 deny 规则也会尽力应用到从 Bash 命令中提取出的路径。`Bash(...)` 的 deny/ask 规则会逐个检查命令里实际会运行的每条命令：`while`/`for`/`if` 循环体、子 shell 与 `{ }` 分组、`$(...)` 替换、`sudo`/`timeout`/`xargs` 等包装以及 `sh -c`/`eval` 的内容都算在内，所以 `Bash(curl:*)` 也拦得住 `while true; do curl …; done`。规则名有家族别名：`Bash` 涵盖 `Monitor`，`Edit` 涵盖所有写入工具，`Read` 涵盖 `Grep`/`Glob`。

项目 `.hanekawa/settings.json` 里的 `permissions.mode` 和 `mcp.trustedServers` 会被忽略并给出诊断，请在用户或本地设置中设置。`Config` 工具不能修改权限模式。`WebFetch` 只跟随同一主机内的重定向；跨主机重定向不算失败，会把目标地址返回给模型，它的下一次请求重新经过权限闸门。

## 扩展

### 技能

技能放在 `<项目>/.hanekawa/skills/<name>/SKILL.md`，或所有项目共享的 `~/.agents/skills/<name>/SKILL.md`（同名时项目内的优先），带 YAML frontmatter：

除了这两个文件夹，还会读取其他工具的技能目录，写好的技能不改动就能用：项目里的 `.claude/skills/`、`.agents/skills/`，以及个人目录下的 `~/.claude/skills/`、`~/.codex/skills/`、`~/.gemini/skills/`。这些目录只读——可以在设置里关掉某个技能，但不能在 Hanekawa 里卸载，删除要去原工具里做。

```markdown
---
name: debugging
description: Use when diagnosing bugs
allowedTools: [Read, Grep, Bash]
model: claude
effort: high
attachments:
  - references/checklist.md
hooks:
  stop:
    - command: "echo skill finished"
---

技能说明写在这里。用 $ARGUMENTS 表示斜杠命令参数出现的位置。
```

技能在启动时发现，有两种用法：

- 通用的 `Skill` 工具，让模型在回合中按名字加载技能
- 以 frontmatter 名字命名的斜杠命令，例如 `/debugging args`

`inclusion` 控制技能如何进入上下文：`manual`（默认，出现在技能列表里，按需加载）、`always`（全文放进系统提示）、`fileMatch`（不进列表，会话读到匹配 `paths` glob 的文件时自动激活）。设置里的 `skills.disabled` 或设置页的技能开关可以关掉某个技能。

技能斜杠命令会在后台把技能正文作为普通查询提交，对话记录里只显示斜杠调用本身，例如 `/debugging args`。正文中的 `$ARGUMENTS` 会被替换成命令参数；没有占位符时，非空参数以 `Arguments: ...` 追加在后面。正文可以包含 ``!`git status` `` 这样的内联 shell 片段，它们在提交查询前经过正常的 Bash 权限闸门执行。

斜杠技能还可以在 frontmatter 中声明文本 `attachments`、`hooks`、`allowedTools`、`model` 和 `effort`，只对该次技能回合生效：`allowedTools` 过滤模型可见和可执行的工具，`model`（必须是 `models` 中的 key）和 `effort` 是临时覆盖，`hooks`（支持 `userPromptSubmit`、`preToolUse`、`postToolUse`、`preCompact`、`postCompact`、`stop`）在该回合与会话钩子合并。附件路径是技能目录内的 UTF-8 文本文件，追加到提示末尾；不支持图片和 PDF 附件。与内置斜杠命令重名时内置命令优先。

### 子代理

模型通过 `Agent` 工具派出子代理。内置类型有 `general`、`explore` 和 `plan`（后两者为 `readonly`）。所有子代理默认使用 `high` 思考强度，自定义 agent 可通过 frontmatter 的 `effort` 覆盖，`Agent` 调用本身也可以传 `effort` 为这一次按次指定（优先于 frontmatter）。自定义 agent 定义从 `~/.hanekawa/agents/`、`<项目>/.hanekawa/agents/` 和 `~/.hanekawa/projects/<key>/agents.local/` 读取，`/agents` 可以查看和管理。子代理使用的模型由 `routing.subagent` 决定，也可以用环境变量 `HANEKAWA_SUBAGENT_MODEL` 或 `HANEKAWA_SUBAGENT_MODEL_<TYPE>` 覆盖。

旧的 `routing.subagent.fork` 配置不再生效，保存配置时会移除。

`Agent` 和 `StartThread` 的工具说明会列出可选模型的配置 key、实际模型名、已配置的上下文长度、模型接受的思考等级（`supportedEfforts`），以及省略 `model` 时的默认模型和线程的默认思考强度；目录不包含 API key 或服务地址，配置重载并重建运行时后更新。主模型可传入 `model: "配置中的 key"` 为本次新建的子代理或线程选模型，传 `effort` 为这一次指定思考强度，都不修改全局设置。`Agent.model` 优先于环境变量、自定义 agent 的 `model` 和路由，`Agent.effort` 优先于自定义 agent 的 `effort`，都没有时为 `high`；`StartThread` 省略时使用全局线程默认模型和默认思考强度。所选模型不接受某个等级时，会降到它接受的最近等级：`StartThread` 的回执始终带实际使用的等级，`Agent` 只在实际等级与请求不同时提示降级；无效 key 会明确报错并列出可选项，不会悄悄换模型。

### MCP

在设置的 `mcpServers` 里配置 MCP 服务器（也可以在设置页「技能和 MCP」中增删改），传输方式为 `stdio` 或 `sse`：

```json
{
  "mcpServers": {
    "filesystem": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"]
    }
  },
  "mcp": { "trustedServers": ["filesystem"] }
}
```

`mcp.trustedServers` 只能在用户设置或本地设置中授予。MCP 工具默认延迟加载，由模型通过 `ToolSearch` 按需取用。

仓库根目录的 `.mcp.json`（Claude Code 的项目文件）也会被读取，不需要改动就能用；同名时 `.hanekawa/mcp.json` 与各设置层里的条目优先。两处的服务器都要先信任：启动时会逐个弹窗询问，拒绝的服务器记为 `not trusted`，接受后写进本地设置的信任列表，设置页里来自 `.mcp.json` 的行会标出来源。

### 钩子

设置里的 `hooks` 在指定事件运行 shell 命令，事件有 `userPromptSubmit`、`preToolUse`、`postToolUse`、`preCompact`、`postCompact`、`subagentStart`、`subagentStop`、`stop`。每条为 `{ "command": "...", "matcher": "...", "timeoutMs": 5000 }`（`matcher`、`timeoutMs` 可选），跨设置层拼接：

```json
{
  "hooks": {
    "postToolUse": [{ "matcher": "Edit", "command": "npm run format" }]
  }
}
```

默认超时 30 秒；超时或停止会清理该命令及其后代进程，包括父进程已退出的情况。Windows 通过系统自带的 Windows PowerShell 和 Job Object 管理进程树。

### Agent 循环

`src/harness/loop.ts` 驱动主推理循环：

```text
用户输入 -> 准备记录 -> 必要时压缩 -> 构建上下文 -> 调用模型 -> 执行工具 -> 重复
```

工具执行采用有序分批：连续的可并发安全工具并行执行，不安全的工具逐个执行并充当顺序屏障。`ToolRunner` 负责工具调用、审批和工具结果记录。

### 上下文与缓存

`src/harness/contextBuilder.ts` 组装：

- 静态系统指令
- 项目上下文（指令文件）
- 可选的自定义系统文本
- 技能
- 自动记忆索引
- 环境信息
- 当前日期
- 压缩后恢复的上下文
- 会话历史

Anthropic 提示词缓存在所有 Anthropic 兼容端点（包括代理）上默认为 `auto`，无论端点主机名是什么，缓存标记的位置都一样：

- 静态系统提示块
- 最后一个稳定的工具定义（MCP 工具和延迟加载的工具排在标记之后）
- 最后一条持久消息，以及上一次请求的锚点消息（每轮重建的临时尾部消息会被跳过）

如果端点以 HTTP 400/422 明确拒绝提示词缓存或 `cache_control`，Hanekawa 会去掉缓存标记重试一次该请求。只有不带缓存的重试成功后才记录这次拒绝，同一进程中相同端点 URL 和模型的所有服务商实例共享这一结果；新会话、切换模型和子代理都复用它，重启进程后清除。结果记录前发出的并发请求可能各自探测并回退。无关的错误走正常重试策略；缓存命中为零不会关闭缓存。

在 `~/.hanekawa/config.json` 的端点或模型上把 `promptCaching` 设为 `"auto"`、`"on"`（不做兼容回退）或 `"off"`，模型上的值覆盖端点默认值。`"on"` 即使之前记录过拒绝也会发送缓存标记。`HANEKAWA_DISABLE_PROMPT_CACHING=1` 无视该设置，直接关闭 Anthropic 缓存标记。

Anthropic 兼容端点返回的思考块连同签名原样回传给产生它的模型和端点；换成别的模型或端点后不再发送，换回原模型/端点后恢复。端点不返回签名时，这段明文思考默认仍以带 `signature: ""` 的 thinking 块回传，以兼容要求历史必带思考的网关；如果端点反过来拒绝空签名块，在 `config.json` 的模型上写 `"allowEmptySignature": false`，改为作为普通 assistant 文本回传。

缓存 TTL 默认 1 小时（设置页「1 小时提示词缓存」，或 `cache.ttl1h: false` / `HANEKAWA_PROMPT_CACHE_1H=0` 改回 5 分钟），兼容端点同样适用；普通缓存不发送 beta 请求头。缓存用量统计和缓存失效诊断在兼容端点上同样运行。缺失的缓存用量不会被当成零命中；服务商调试输出把未缓存输入、缓存写入和缓存读取分开报告。

OpenAI 官方端点（`api.openai.com`）的 Chat Completions 请求带上基于模型、系统提示和工具生成的稳定 `prompt_cache_key`；兼容服务不发，因为部分服务会拒绝不认识的参数。缓存读取数兼容 `prompt_tokens_details.cached_tokens`、DeepSeek 的 `prompt_cache_hit_tokens` 和 Kimi 的顶层 `cached_tokens`；报告了 `cache_write_tokens` 的服务会单独计入缓存写入。

上下文管理完全在客户端进行：Hanekawa 不发送 `context_management` 或 `cache_edits` 请求。它为压缩摘要预留 20,000 token，保留活跃的对话前缀，长时间空闲后清除旧的工具结果，并在接近有效窗口上限时自动压缩。预算包含指令文件、工具定义、预载及继承的历史、临时内容和图片；发送前优先尝试压缩，仍需省略历史或附加内容时，会在对话中提示。自动压缩连续失败 3 次后暂停；`/compact` 不受此限制，成功后自动压缩恢复。

压缩摘要、它接着的任务和最新一条真实指令属于**不能裁掉**的内容：预算先给它留位置，再从剩余空间恢复文件全文和技能。装不下时会先尝试一次压缩；仍然装不下就停在这一回合并报「对话超出了模型的上下文」，已写入会话的内容原样保留——换一个上下文更大的模型、压缩对话或精简任务说明后可以重来，不会把请求带着错误的上下文发出去。

#### OpenAI Chat Completions

请求一律流式（`stream_options.include_usage`）。长时间没有数据时先提示，10 分钟无数据才中断并按网络错误重试；流结束却没有 `finish_reason` 也按网络错误重试，`content_filter` 直接报错。

请求形状按 `baseUrl` 自动识别：

| 服务 | 开启思考 | 关闭思考 | 其他 |
|---|---|---|---|
| OpenAI 官方 | `reasoning_effort` | 不发 | `developer` 角色、`max_completion_tokens`、`store: false` |
| DeepSeek | `thinking: {type: "enabled"}` + `reasoning_effort` | `thinking: {type: "disabled"}` | 历史 assistant 消息都带 `reasoning_content` |
| 通义（DashScope） | `enable_thinking: true` | `enable_thinking: false` | |
| 智谱 | `thinking: {type: "enabled"}` | `thinking: {type: "disabled"}` | |
| OpenRouter | `reasoning: {effort}` | 不发 | `reasoning_details` 原样回传给产生它的模型 |
| Kimi | 不发 | 不发 | |
| 其他 | 同 OpenAI 官方的 `reasoning_effort` | 不发 | `system` 角色、`max_tokens` |

思考等级原样发送；模型不支持的等级用模型的 `supportedEfforts` 排除。识别不出的中转站可以在 `config.json` 的端点上手写 `thinkingFormat`：`openai`、`deepseek`、`qwen`、`zai`、`openrouter` 或 `none`。

思考默认开启：并不是每个模型都会思考，而兼容服务无法事先告知。端点以 HTTP 400/422 拒绝了思考字段时，Hanekawa 去掉思考字段重试一次；只有重试成功才记住这次拒绝，同一进程中相同端点和模型之后不再发送，重启后清除。全局「扩展思考」关闭，或模型配置了 `"thinking": {"type": "disabled"}` 时，按上表「关闭思考」一列发送。

回复里的推理文本依次读取 `reasoning_content`、`reasoning`、`reasoning_text`，保存在消息上并在下次请求时以 `reasoning_content` 回传。

#### OpenAI Responses

`openai-responses` 同样流式请求，系统提示放在 `instructions`，带 `store: false`；工具一律 `strict: false`（不写的话 Responses 会尝试把工具转成严格模式，可选参数过不了）。工具结果里的图片直接放进 `function_call_output`。

Responses 请求使用稳定的会话 ID 作为 `prompt_cache_key`，并回传同一回合的 `x-codex-turn-state` 路由令牌。对支持显式缓存的模型（GPT-5.6 及后续模型），发送 `prompt_cache_options: {mode: "explicit"}`，在持久用户消息和工具结果末尾放置 `prompt_cache_breakpoint`；日期、权限等每次重建的临时提示位于缓存边界之后。调度主会话已接收的线程快照和笔记作为持久消息参与缓存。一次性请求声明 `promptCaching: false` 时不设置写入边界。如果模型或兼容服务明确拒绝缓存键或显式缓存字段，则去掉对应字段重试，成功后在同一进程内记住该端点和模型的拒绝。

开启思考时发送 `reasoning: {effort, summary: "auto"}` 和 `include: ["reasoning.encrypted_content"]`；关闭时整个 `reasoning` 都不发——`effort: "none"` 会被不支持它的模型直接拒绝。思考字段被拒时的退回与 Chat Completions 相同。

Responses 的加密推理本地计数沿用 Codex 的估算：从编码长度回推字节数，扣除估计的 650 字节封装开销，再按 4 字节/token 换算；思考摘要和传输元数据不重复计入。有服务端用量时使用该用量加上后续新增内容的估算。本地估算用于上下文预算，费用和缓存命中率仍以服务端报告为准。

模型思考过的回复，会把这次的输出项（推理、文本、函数调用）原样存在消息上，下次请求同一个模型时原样回传：加密推理只能交还给产生它的模型，而且要连同与它配对的输出项一起。换了模型，或历史里缺了其中某个函数调用，就退回为只发文本和工具调用、不带推理。回复以 `max_output_tokens` 截断记为输出上限；其他未完成状态和 `response.failed` 直接报错；流结束却没有收到完成事件按网络错误重试。

### 工具

每个内置工具一个目录 `src/tools/<Name>Tool/`，包含实现文件和 `prompt.ts`（工具描述及工具名常量），统一在 `src/tools/index.ts` 注册：

- 文件：`Read`、`Write`、`Edit`、`MultiEdit`、`Delete`、`NotebookEdit`、`Grep`、`Glob`
- Shell：`Bash`、`KillShell`。后台命令的输出边跑边写进会话的 tool-results 目录（超过 5 MB 只保留开头和结尾），模型用 `Read` 读取；命令结束时通知会附上最后 20 行，并唤醒空闲的会话，所以不需要轮询。命令卡在前台时你也可以直接发消息：仍在跑的命令会移到后台继续跑，你的消息在模型下一步开始时并入这一轮，不必等命令结束
- 监控：`Monitor` 在后台跑一个脚本，它 stdout 的每一行是一个事件，在模型下一步开始时合并送进对话（每个监控最多带最近 50 行，多出的只留计数和输出文件路径）。事件只在模型工作时送达：会话空闲时不唤醒，攒到用户下一条消息一起带上；工作中一次送达就超出上限的监控会被自动停掉。默认 5 分钟后结束，最长 1 小时，`persistent` 不限时；用 `KillShell` 停止。命令按 Bash 的分级和 `Bash(...)` 规则判定，子代理不提供
- 网络：`WebFetch`、`WebSearch`。`WebFetch` 抓一个 URL 并返回正文 markdown：先删掉脚本、样式、导航、cookie 横幅、侧栏和页脚再转换，`<script>` 里的代码不会再混进结果（实测 qq.com 从 12.6 万字符 HTML 降到 1.7 千字符正文）；表格转成 GFM 表格，相对链接改写成绝对地址，GBK/Big5/Shift_JIS 按页面声明的编码解码，不再出现乱码。`pattern` 只回命中行（带行号与两行上下文），`offset` 按行翻页，单次约 4 万字符，页尾会写明下一页从哪一行开始；PDF 与二进制会直接说明原因，并指向 `Browser` 或 `pdftotext`。同一页面 15 分钟内重复读取走缓存。`WebSearch` 一次可发 1–4 条 query（每条可带 `recencyDays`、`domains`，整轮可带 `blockedDomains`），按引擎链逐个尝试（DuckDuckGo → Bing → Baidu → Wikipedia，中文 query 先问 Baidu；配了 `HANEKAWA_SEARCH_URL` / `HANEKAWA_BRAVE_API_KEY` 时它们排最前）。刚连不上的引擎会被跳过约 2 分钟、被反爬挑战的跳过约 1 分钟，所以开着代理时直接用上好引擎，代理关掉时也只白等一次超时而不是每条 query 都等；窗口过期后会自动重试，不用重启。结果还要校验确实提到了 query——引擎对不上的 query 会拿兜底结果充数，这种结果会被判掉而不是当成答案；全部失败时逐条列出每个引擎失败的原因
- 规划与交互：`EnterPlanMode`、`ExitPlanMode`、`AskUserQuestion`、`TaskCreate`、`TaskList`、`TaskGet`、`TaskUpdate`
- 其他：`Agent`、`SendMessage`、`Skill`、`ToolSearch`、`Config`

`Edit` / `MultiEdit` 可以直接替换从搜索、Bash 或对话中已知的准确文本，无需为了满足前置条件再调用一次 `Read`。替换始终匹配磁盘上的当前内容；文件其他位置有修改时保留这些修改，目标文本找不到、匹配不唯一或批量范围重叠时不写入。需要了解周边逻辑时仍应先读取。已有文件的整文件覆盖（`Write`）、删除和 notebook 编辑仍要求先读过且文件未过期。

字符串编辑保持原编码、BOM、换行风格和文件权限，只接受 UTF-8 或带 BOM 的 UTF-16LE 文本。对应文件的 `Read` deny/ask 规则也约束编辑工具的内部读取；`Read` allow 规则不会授权写入。

桌面端还通过 `extraTools` 注入 `Browser`、`Computer` 和项目调度工具（`StartThread`、`ListThreads`、`MessageThread`、`FetchThread`、`ResolveThread`、`StopThread`、`AskCoordinator`，按会话角色开放）。

### 电脑操作（Computer）

桌面端通过自有 macOS 原生 helper 控制已运行的应用，使用公开 Accessibility、CoreGraphics 和 ScreenCaptureKit API。安装依赖后运行 `npm run build:desktop` 会用 Xcode Command Line Tools 的 Swift 编译器构建 helper；无需安装额外 CLI、配置 MCP 或提供 API Key。网页操作继续使用内置 `Browser`。当前原生后端支持 macOS 13+，窗口截图需要 macOS 14.4+；Windows/Linux 仅保留 Browser 能力。

模型通过工具搜索发现 `Computer`，直接传结构化参数。先用 `list_apps` 找到应用，再用 `bind` 取得本会话的持久 `appId` 和初始 AX 界面树，不需要阅读 CLI 文档或拼接字符串参数。例如：

```json
{"operation":"bind","app":"com.apple.calculator"}
```

`bind` 只绑定已运行的应用，不启动、激活或退出应用。应用有多个窗口时返回 `windows`（含实际 AX `role`），由 `get_state` 的 `windowId` 选择；选择后持续沿用该窗口。元素引用格式是 `s<快照 UUID>:e<索引>`，必须来自最新 AX 观察。`click` 使用 AXPress，`set_value` 设置可写 AXValue，`perform_action` 调用该元素实际暴露的 AX 动作。这些语义操作不移动鼠标。动作自动返回新的 AX 状态；模型应检查状态是否符合任务目标，不能把事件发出视为完成。

`get_state` 默认显示差分；未变化的元素索引需换用结果头部的新快照前缀。`disableDiffing: true` 返回完整树。观察受深度、节点数、时间和输出长度限制，`complete: false` 或 `truncated: true` 表示尚未读完，可用最新 `rootRef` 读取子树。文本输出超出预算时优先保留浅层节点和分支入口，再按原遍历顺序输出，保留原索引；行与行之间可能省略后代，避免长列表遮蔽后续浅层控件。原生读取截断时返回本次读到的树，不把未读到的元素报告为删除。截断结果和子树结果不会作为下次窗口差分的基线，恢复窗口读取时重新返回完整树（仍受上述限制）。每次观察和每次动作尝试都会让旧引用失效；截图也会清除 AX 引用。

AX 结果携带 `revision`、`mode: full / diff` 和 `baseRevision`（完整树为 null）；差分只基于上一份实际发布的完整可用结果，不基于内部等待样本。内部身份按同一 AX 对象、窗口、父级及内容指纹保守匹配，不能用作操作引用；标题相同不代表同一个元素。内容变化或控件被复用时会换身份，可能显示为删除/新增。重排会标记 `(from 上一快照ref)`；删除也使用上一快照的完整 ref。先从旧基线清除删除项和移动来源，再按新索引应用输出行，最后统一使用新快照前缀。原生协议已升级为 `hanekawa-computer/4`，旧 helper 会被明确拒绝，需重新构建并重启。

`get_state` 另有 `scope: "application"`，读取该应用的菜单栏、聚焦的弹出界面及窗口；无需先选窗口，也可用于没有窗口的应用。`wait_for` 的元素条件也可指定该 scope。应用观察不提供窗口坐标，不能用于物理输入；需要点击坐标或按键时，先用默认 `scope: "window"` 选择窗口并重新观察。切换 scope 返回完整树。跨进程的系统选择器不会被当作原应用控件读取；安全字段及其子树不输出正文。自有 AppKit 已完成菜单 → sheet → 输入 → 明确确认的真实链路；系统托管选择器、其他弹窗和 Electron 兼容性仍待分别验收。

节点输出实际暴露的 `actions`、`writableAttributes`（限 `AXValue / AXFocused / AXSelectedTextRange`）以及可取得的所属 `windowId`。`focus` 单独设置可写 `AXFocused`，不隐式激活应用或发送按键。`select_text` 单独设置可写的 AX 文本选区：`selection: {start, length}` 使用 UTF-16 单位，零长度用于移动光标；`selection: {text, prefix?, suffix?}` 查找唯一的精确文本，前后文必须相邻。重复、未找到、越界或切开 emoji 代理对时在修改前拒绝；不自动改走键盘。结果包含可读取的 `selectedTextRange`。选择和设置字段值不等于追加输入；现有 `type_text` 仍发送 Unicode 键盘事件。范围/匹配规则已通过无 GUI 自检及自有 AppKit 控件的实际选区读回。 `type_text` 在当前光标处输入或替换当前选区，长度上限是 4096 个 UTF-16 单元；每个 Unicode 字素使用成对的按下/释放事件，显式清空修饰键标志并核对编码，不改剪贴板。中途失败会说明已派发的 UTF-16 数量，这不是应用内容读回结果，不能据此重复输入。混合中文、emoji、组合字符、换行与长 emoji 的事件编码及中断规则通过无 GUI 自检；自有 AppKit 控件的实际混合文本输入、选区替换、cmd+a 和拒绝聚焦分支已通过独立状态读回；不能据此扩大为所有应用或输入法均已验证。

动作后不再固定等待 120ms，而是按 100ms 间隔采样：完整 AX 树连续至少 200ms 不变时返回 `wait.status: settled`；最多使用 1000ms 的局部采样预算，持续变化返回 `timed_out`，原生观察不完整时返回 `unsupported`。三种结果都保留最后观察；`action.verified` 仍为 false，界面暂时稳定不证明业务完成。内部采样只在最终结果发布一次新引用和差分，不重复写入模型上下文。

`wait_for` 是只读操作，可等待元素出现/消失（`role`、`labelIncludes`、`valueIncludes`，所填条件须在同一节点满足），或窗口出现/关闭（`windowId` 或 `titleIncludes`）。窗口级元素条件需要先选择窗口，应用菜单可指定 `scope: "application"`；窗口标题条件不自动选中匹配窗口。字符串片段大小写敏感，只匹配实际暴露的 AX 文本前缀，不能读取安全字段或证明整篇长文的内容。返回 `wait.status: matched / timed_out / unsupported`；原生截断树不能证明元素消失。`waitMs` 默认 5000ms、范围 100–60000，用于限制继续采样；已开始的 AX 请求和全部排队、动作、采样仍共用原有 `timeoutMs` 总截止时间。局部超时保留最后快照；总截止时间到期继续报错并回收 helper。等待不重复投递动作。例如：

```json
{"operation":"wait_for","appId":"<bind 返回的 appId>","condition":{"kind":"element","state":"present","valueIncludes":"保存完成"},"waitMs":5000}
```

上述等待逻辑已通过协议模拟、权限回归和构建验证；自有 AppKit 应用中的真实延迟更新和永久不满足条件已分别核对 matched / timed_out。异步 sheet 的出现、关闭及输入/确认也在自有 AppKit 通过；真实业务应用及完整产品流程仍须分别验收。

窗口条件只读取窗口列表，不因选中窗口的 AX 树读取失败而失败；这类等待只返回窗口证据，不生成 AX ref，需要操作时再 `get_state`。内部身份、重排差分及版本基线已有协议回归和原生规则自检，真实 AX 对象相等性及虚拟化列表兼容性仍待更完整的真实场景验证。

`click_at`、`press_key`、`type_text` 和 `scroll` 是物理输入，会激活并抬起目标窗口，可能移动鼠标；它们需要最新 `snapshotId`，按高风险操作走现有权限模式。普通 AX 修改按普通操作处理，观察、绑定和释放按只读处理。`Computer` 的 allow/ask/deny 规则继续生效。工具不会把失败的 AX 动作自动降级为鼠标操作。物理输入前检查前台应用、选中窗口和窗口位置。键盘输入还读回实际聚焦的 AX 控件，核对应用、所属窗口及安全字段祖先；传入 `ref` 时必须与该控件一致，不能只依据系统返回“聚焦成功”。连续文本每个字符事件对之前重新核对焦点，焦点变化时停止后续字符并失效绑定，已排队的旧绑定输入会拒绝；这些检查仍不保证操作与用户输入完全原子化，也不等于完整的用户接管检测。

访达等应用可能把重命名编辑框直接列为 `role: "AXTextField"` 的独立顶层对象，而不放在主窗口树内。选择该对象自己的 `windowId` 并重新观察后，才能使用键盘输入；它必须已经是前台应用的实际焦点，工具不会为它抢焦点或抬起窗口，也不允许在这种对象上使用坐标点击或滚动。输入导致的编辑框自动伸缩不会中断同一焦点的键盘输入。提交后编辑框消失时，宿主核对其已从同一进程移除，保留 `delivered_unverified` 回执和当前窗口列表，不生成旧编辑框引用、不重发回车；下一步须重新选择并观察窗口。

`screenshot` 通过会话附件存储传递真实 PNG，仅支持可接收图片的模型。截图窗口按进程和窗口几何信息与 AX 窗口严格匹配，无法唯一匹配时拒绝截图。结果包含 `boundsInPoints`、`imageSizeInPixels` 和 `coordinateSpace`。`click_at` 使用窗口内的点坐标：将模型看到的附件像素 x/y 分别乘以窗口点宽/附件宽、窗口点高/附件高；系统屏幕坐标可以为负，不能直接套用截图像素。

也可用 `get_state` 的 `includeScreenshot: true` 一次取得窗口 AX 与截图，仅在需要图片时使用；不支持与应用 scope 或 `rootRef` 合用。返回一份当前可操作的 AX 快照，图片另带 `screenshot.revision / sampledAt / windowId / processId`，AX 自身携带 `revision / sampledAt`。`atomic: false` 明确表示它们是依次采样；采样间窗口身份或几何位置改变会拒绝结果。该契约已通过模拟回归，并在本机自有 AppKit 窗口完成真实 PNG 来源和像素到点换算点击核对；附件降采样、多显示器及移动窗口等场景仍未完成。

工具结果中的 `diagnostics` 记录请求/会话/绑定/快照标识、排队和原生方法耗时、观察次数、输出字符数及图片字节数；错误记录保留 code 和 delivery。`helper_spawn` 只表示进程启动，不表示 AX 已就绪；`stability_wait / condition_wait` 包含内部采样，与原生方法耗时重叠，不能直接相加。附件导入另计时。诊断不另存 AX 全文、输入正文、图片或密钥，原有会话工具记录不变；目前没有真实模型任务级统计或性能收益结论。`press_key` 的字符键表示 US ANSI 物理键位，名称不区分大小写，大写须显式 `shift`；字符输出受当前键盘布局影响，Unicode 内容应使用 `type_text`。

macOS 需要为 Hanekawa 授予「辅助功能」，截图还需要「屏幕录制」。开发模式的权限可能归属 Electron，也可能归属启动它的应用或终端；不能只看 Electron 的开关。当前从 Codex 启动的隔离测试曾由系统归属到 `/Applications/ChatGPT.app`，开启该宿主的辅助功能后，正式 helper 才返回已授权。其他启动方式应重新核对，不能套用这个路径。`status` 检查权限并返回系统设置入口，不自动弹出权限申请或修改系统授权数据。重新构建、安装路径或签名变化后应再次检查权限。打包版本的 TCC 归属和真实桌面行为需要在授权后的 Hanekawa 中验收。

开发时可在构建后运行 `npm run verify:computer:electron`：它使用隔离的临时 Electron 配置，通过正式宿主和 helper 只读检查权限，不创建业务窗口或申请授权。命令成功表示这条检查链路可用；应另看输出的权限布尔值。它不替代完整 Hanekawa 或安装包中的真实 GUI 验收。

需要主动申请开发环境辅助功能权限时，运行 `npm run verify:computer:electron -- --request-accessibility`：它只在明确传入该参数时请求 Electron 的系统授权提示，打开对应设置并在 Finder 定位开发用 `Electron.app`，最多等待 120 秒供用户确认；未自动列出时，可在设置中点「＋」添加该应用。开关仍由用户操作，脚本不会修改 TCC。若 Electron 已开启而 helper 仍返回未授权，还需检查启动它的应用或终端。最终仍通过正式 helper 检查实际权限，不能只依据 Electron 自身的授权返回值判断成功。

原生测试单独运行 `npm run test:computer:native`，不包含在默认 `npm test` 中。脚本在临时目录编译、启动自有 AppKit 测试应用，通过生产 `ComputerTool → DesktopComputerHost → helper` 执行确定性操作，再独立读取测试应用状态核对结果；只针对本次启动的测试应用。缺辅助功能权限时报告 `blocked` 并以 77 退出，不把跳过操作算作通过。可用 `npm run test:computer:native -- --fixture-only` 仅检查测试应用的编译、双窗口启动、初始控件、重启和回收；该模式退出 0 不表示 AX 操作已验证。测试不申请系统授权，临时应用和数据退出后清理；本机首次完整原生闭环的成功、失败和剩余范围见 [验证记录](computer-use-reference/CU-NATIVE-CLOSURE-2026-11-04.md)。它不是完整 Hanekawa 权限流程、安装包或真实模型任务验收。

原生调用跨会话串行执行；同一应用进程同时租给一个会话，其他会话需等待前一个调用 `release` 或关闭。`release` 只回收绑定/helper，不关闭目标应用。停止正在执行的调用、超时、清空/切换会话、关闭会话及退出应用都会回收受影响的 helper；截止时间包含排队。未知投递或动作后观察失败时保留投递状态，绝不自动重试。运行中收到权限不足时会回收该绑定和 helper、释放应用占用并拒绝已排队的旧绑定调用，重新授权后需重新绑定。已收到动作投递确认后，后续观察被取消、超时或发现权限不足时仍返回 `delivered_unverified`。取消不能撤销已送达系统的操作；恢复后先重新绑定并观察。

桌面收到休眠、恢复、锁屏或解锁事件时，会撤销所有 Computer 绑定、回收 helper，并取消事件发生前已排队的调用；恢复后不会自动重放输入。已知休眠或锁屏期间的新调用返回 `DESKTOP_UNAVAILABLE / not_delivered`，无需启动 helper；恢复系统后重新核对锁屏状态，锁屏与休眠各自解除后才接受新调用。应用启动时也检查锁屏状态。helper 空闲时崩溃或通信关闭，后续调用会清理失效绑定、等待进程退出并释放应用租约，避免其他会话被旧占用挡住。已获确认的动作保留 `delivered_unverified`，执行中尚未获确认的动作保留 `unknown`，仍在排队的调用为 `not_delivered`。这套行为已通过模拟 helper 和隔离 Electron 的注入事件验证；没有自动触发真实锁屏或休眠，系统事件时序和强制终止时的系统级输入释放仍待真实验收。可运行 `npm run verify:computer:electron -- --verify-lifecycle` 重跑隔离验证；它不会实际锁屏、解锁或休眠电脑。

桌面修改不受文件工具的项目路径限制保护，也不能通过 `/rewind` 撤销。工具不暴露任意 JavaScript、shell 参数、应用启动参数、拖动/长按、剪贴板和通知管理；API 的持久对象与观察机制由受信宿主实现。源码见 [ComputerTool](src/tools/ComputerTool/)、[桌面宿主](src/desktop/computer/) 和 [Swift helper](native/computer/ComputerBridge.swift)。helper 不监听网络，不保存跨会话 AX 状态，截图经私有 stdio 交给附件存储；文本记录不保存 base64。

可用 `npm run test:computer:apps` 重跑真实计算器、文本编辑和访达的确定性基准，默认每项 3 轮；也可指定 `-- --scenario=finder --repetitions=1`。计算器/文本编辑已有用户实例时测试会停止并保留该实例，访达只操作专用临时目录。`--evidence-dir=<目录>` 可保存计算器 PNG；图片结果需单独目视核对。测试会先确认测试窗口关闭、进程退出，再删除资料；无法安全关闭时保留临时目录并报告路径，避免重命名期间删除目录引发访达 -8072。`-- --scenario=finder --repetitions=1 --interrupt-rename` 故意在重命名中途失败，用于检查清理，预期退出码为 1。这些是生产驱动的确定性测试，不代表安装包或自然语言模型任务验收。

构建产物 `dist/desktop/computer/native/hanekawa-computer` 放在 ASAR 外的 `Resources/computer/native/`，由现有 electron-builder 流程分发；构建会清除旧 agent-desktop 原生资源。实现参考了 Codex 逆向分析中的持久绑定、版本化引用、差分观察和受信执行边界，独立编写公开 API 驱动，不依赖 Codex 的专有服务或提取代码。

### 会话

会话存放在 `~/.hanekawa/projects/<key>/sessions/`，由元数据和只追加的 JSONL 记录组成，记录包括消息、工具调用、工具结果、审批和压缩边界。每个会话旁边还有一个 `<id>.metrics.jsonl` 用量文件，目录里有 `index.json` 索引。

## 环境变量

- `HANEKAWA_DEBUG_PROVIDER=1`：记录服务商请求和响应内容
- `HANEKAWA_PROMPT_CACHE_1H=0`：把 Anthropic 提示词缓存 TTL 从默认的 1 小时改为 5 分钟
- `HANEKAWA_DISABLE_PROMPT_CACHING=1`：关闭提示词缓存
- `HANEKAWA_MAX_OUTPUT_TOKENS=N`：覆盖最大输出 token 数（上限 1,000,000）
- `HANEKAWA_STREAM_IDLE_WARNING_MS=N`：流空闲多久发出警告（默认 90 秒；旧名 `HANEKAWA_STREAM_IDLE_TIMEOUT_MS` 仍可用）
- `HANEKAWA_STREAM_IDLE_HARD_TIMEOUT_MS=N`：流空闲多久中止请求（默认 10 分钟）
- `HANEKAWA_SUBAGENT_MODEL` / `HANEKAWA_SUBAGENT_MODEL_<TYPE>`：覆盖子代理使用的模型
- `HANEKAWA_SEARCH_URL`：`WebSearch` 优先使用的 SearXNG 地址（JSON API 关闭时会退回解析它的 HTML）。自建实例是唯一能自己控制的检索源，在网络封锁了内置引擎时最有用
- `HANEKAWA_BRAVE_API_KEY`（或 `BRAVE_API_KEY`）：设置后 Brave Search 排在引擎链最前
- `HANEKAWA_BASH_PATH`：指定 Bash 可执行文件（仅 Windows 生效）
- ToolSearch 相关变量见上文「ToolSearch」
